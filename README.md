# Elon Musk 5-Step Algorithm · 五步工作法 Skill

> "The best part is no part. The best process is no process."
> 最好的零件是没有零件,最好的流程是没有流程。

一个 Agent Skill(OpenCode / HyperCode / Claude Code / Cursor 兼容),把 Elon Musk 的工程算法固化成可执行的评审清单,并补上未知领域模式、研发/实验运行原则、RSI 闭环与停止条件。

**四层结构:** 怎么决策(五步) → 怎么保持推进(运行原则) → 怎么确认改进是真的(RSI 闭环) → 什么时候停(锚在目标上)。

## 七步(顺序不可颠倒)

| # | 步骤 | 一句话 |
|---|---|---|
| -1 | 参照系 | **未知领域专用。** 凭什么你认为是对的?是你在设限制,还是"常见路径"在替你设? |
| 0 | 钉住目标 | 先回答"我在往哪造",钉住**可测指标**和**预算**(时间/成本/轮次) |
| 1 | 质疑每一项要求 | 所有要求都可能是错的,尤其是聪明人提的;每条要求必须署人名 |
| 2 | 删除 | 删到你会把 10% 加回来,才算删够 —— **但先分清可逆 / 不可逆** |
| 3 | 简化 / 优化 | 只在前两步之后做;别优化一个该删的东西 |
| 4 | 加快循环时间 | 只在前三步之后做;别在坑里加速 |
| 5 | 自动化 | 最后一步;别自动化一个该删的流程 |

> 大多数人的错误是一上来就优化、加速、自动化。
> Musk 自己承认:"造 Model 3 时,我真的是先自动化、再加速、再简化,最后才删除。"

## 第 -1 步:当问题还不存在

五步默认"存在一个可以质疑的要求"。但在**人类未知领域**,没有要求、没有先例、没有基准 —— 第 1 步会直接失效。

这时先回答两个问题:

1. **凭什么你认为是对的?** —— 你的依据是什么?如果依据是"常见路径",那只是一个样本,不是答案。未知领域里没人能证明自己是对的,所以你不需要"对",你需要**可被证伪**。
2. **是你在设置限制,还是"常见路径"在替你设置限制?** —— 把每条限制过一遍:物理约束,还是约定约束?

| 类型 | 例子 | 处理 |
|---|---|---|
| 物理 / 数学 / 法律硬约束 | 光速、热力学、材料强度、法规 | **真的**,接受它 |
| 约定约束 | "行业惯例""大家都这么做""去年也这样""别人都失败了" | **不是约束,是默认值**,可以推翻 |

> Musk:"唯一的铁律是物理定律,其余都只是建议。"

**判据:你的假设能被证伪吗?** 不能证伪的,不是假设,是信念 —— 信念不产生信息。

## 研发 / 实验运行原则:让设备一直跑

五步管"怎么决策",这一条管"怎么保持推进"。做研发和实验的时候用。

**核心:永远有东西在跑。**

- **设备 / 算力不空转。** 训练尽量不要停,实验台尽量不要空。让下一组实验在上一组还没出结果时就排上 —— 排队等结论是最大的浪费。
- **一个方向不行 → 换方向,不要停。** 卡住不是停工的理由,是换路的信号。
- **卡住时三选一,但别选"等着"**:

| 出路 | 做什么 |
|---|---|
| 换方向 | 试另一条路径 / 另一组参数 / 另一个假设 |
| 定位问题 | 分层排查:到底是哪一环错了?找到真正那一层 |
| 修,再试 | 修完立刻重跑,别让"修"变成新的等待 |

- **失败必须变成下一轮的输入。** 一次实验跑完,必须产出"下一次跑什么"。跑完没有下一轮 = 白跑。
- **并行优先,串行是最后手段。**

**和"别在坑里加速"不冲突:** 那条说的是别在**同一条错路**上更快;这条说的是别让**整体的实验吞吐**掉下来。判定一个方向是坑 → 关掉它、把资源移到别的方向,不是停下来。

> 反直觉的点:"停下来想清楚"常常是拖延的高级形式。正确姿势是**让实验继续跑着,同时想** —— 想和跑并行,不是先后。

## RSI 闭环:让改进本身可验证

```
提议 → 评估(冻结评估器) → 晋升门 → 保留 / 回滚 → 记录血缘 → 下一代
```

**七条硬规则:**

1. **评估器不可改。** 改进者不能碰判分规则 —— 测试、门禁、反作弊、循环编排本身,全部冻结。**改得了裁判,分数就没有意义。**
2. **留出集必须封存。** 搜索过程看不到最终测试。看得见的测试,迟早会被拟合。
3. **没进晋升门,不算改进。** "我觉得变好了"不是证据。
4. **被拒的必须回滚。** 半成品会让下一轮的基线不可信。
5. **每代记血缘。** 没有血缘 = 复现不了 = 等于没发生。
6. **失败要留下残渣,喂给下一轮。** 失败是下一轮的课程来源。
7. **建与审分离。** 提议的人不给自己打分。

**判据:这一轮的改进,别人能复现吗?** 能 → 它是真的;不能 → 它只是你的感觉。

## 什么时候停

前面全在说"别停"。这一节说**什么时候必须停** —— 判据只有一条:**任务目标**。不看进度条,不看心情,不看累不累。

| # | 条件 | 动作 |
|---|---|---|
| 1 | **目标达成** | **停**,收工。达成标准在第 0 步就写好了(可测量) |
| 2 | **目标被证伪 / 不再成立** | **停**这个方向,回第 0 步重立目标。这不是失败,是目标层的结论 |
| 3 | **代价超过目标价值** | **停**,或降级目标。靠预算闸判定 |

**不算停止理由的:** "删得差不多了" / "跑腻了、没灵感、团队累了"(这是换方向) / "这个方向失败了"(这是换路,不是停)。

**刹车 vs 换路:**

| 情况 | 动作 | 层 |
|---|---|---|
| 一个方向不行 | **换方向** | 运行原则 |
| 目标不可能 / 没意义 | **停**,回第 0 步重立目标 | 目标层 |
| 代价超价值 | **停**,或降级目标 | 目标层 |
| 目标达成 | **停**,收工 | 目标层 |

**预算闸:** 第 0 步钉死的时间盒 / 成本上限 / 轮次上限,到线就**强制复盘**,三选一必须明确选 `继续 / 换路 / 停`。**默认是停,不是继续** —— 想继续要给出理由。

## 删除的刹车(第 2 步的可逆性分级)

| 删什么 | 可逆? | 规则 |
|---|---|---|
| 代码、流程步骤、字段、会议、文档 | ✅ 可逆 | **疯狂删**,删错了加回来 |
| 数据、客户、对外承诺、已发布的 API、合规流程、钱 | ❌ 不可逆 | **不能按 10% 规则删** —— 先建回滚方案 + 明确批准人 |

判据:**删掉之后,你能把它完整加回来吗?** 不能 → 先解决"怎么加回来"。

## 什么时候不该用这套

这套是**工程建造法**,不是通用管理法:

| 场景 | 为什么不行 |
|---|---|
| 和人相关且不可逆的事(裁员、绩效、对外承诺) | 删不回来,且"质疑+删除"会直接伤人 |
| 需要多方共识的决策 | 单方面删除会变成政治事故 |
| 安全关键 / 强监管系统 | "疯狂删除"要换成可逆性分级 + 强制留出集 |
| 目标本身还没定 | 先做第 0 步 |

## 入口:先看你手上是什么场景

| 你要干的 | 进哪一层 |
|---|---|
| 从零开始,连问题是什么都不知道 | **第 -1 步** |
| 评审一个方案 / 功能 / 流程 | **第 0 → 5 步** |
| 跑研发、跑实验、保持推进 | **运行原则** |
| 改进了一个东西,想确认是不是真的 | **RSI 闭环** |
| 想知道什么时候收工 / 该不该放弃 | **什么时候停** |

## 用法

**作为 Skill 加载**:把文件夹放进你的 skills 目录:

```bash
# OpenCode / HyperCode
cp -r . ~/.config/hypercode/skills/elon-musk-5-step/

# Claude Code
cp -r . ~/.claude/skills/elon-musk-5-step/
```

**作为评审清单**:直接打开 `SKILL.md`,按上面「入口」表选层,再逐条走。任何一步答不上,就停在那一步。
